# GLM-5.3 커널 최적화 강화 — Campaign II (srv4, TP=4)

## 배경
리포 인구조사(`STEP_KERNEL_MAP.md`, #108) 기준 열린 커널 축은 정확히 4개이고, 나머지는 전부 닫힌 축(재조사 금지)이다. 이 계획은 4축 전부를 건드리되, 코드로 가능한 것은 지금 구현하고 부팅이 필요한 것은 srv4 런북으로 준비한다.

## 구현 항목

### 1. srv4에서 이미지 원본 소스 복원 (읽기 전용 SSH)
- `docker exec cat`으로 glm53:v13-b12x 이미지의 `vllm/model_executor/kernels/mhc/tilelang.py` + `vllm/model_executor/layers/mhc/` 원본 확보 (CUDA 실행 없음 — 서빙 컨테이너 CUDA 금지 법칙 준수)
- 모델 config에서 q_lora/kv_lora/KDA 랭크 차원 확인 → b_proj가 `min(shape)>=512` 가드를 통과하는지 판정
- b_proj/indexer 계열의 정확한 런타임 모듈 이름 검증 (현재는 트레이스 추정)

### 2. b_proj/indexer fp8 확장 — `glm53_fp8_dense.py` (bf16 GEMM 145개/step, 7.7%)
- `_INCLUDE`에 `.self_attn.(q_b_proj|kv_b_proj|f_b_proj|g_b_proj)$` + indexer 계열 패턴 추가
- **새 독립 게이트 `VLLM_GLM53_FP8_DENSE_BPROJ`, 기본 off** — #110 교훈("진행해"는 "기본화"가 아니다): 전적 0인 확장을 프로필 기본으로 올리지 않는다
- `min(shape)>=512` 가드는 유지 (저랭크 사영은 양자 커널 오버헤드가 바이트 이득을 넘을 수 있고 정밀도 민감 축이므로 — skipped 로그가 실측 데이터를 준다)
- 기존 stale-copy 검사·per-layer 폴백 그대로 재사용
- `tests/test_logic.py`에 패턴 매칭 테스트 추가 (매치해야 할 이름 / 매치하면 안 되는 이름: `mlp.experts`, `in_proj_qkvbfg_a` 등 / 게이트 기본 off)

### 3. glm5 mhc TileLang 접수 (185 커널/step, 9.8%)
- 1단계에서 복원한 원본을 `dsv4_mhc_tilelang` 선례(P2b small-M 승리 (6,4), R2 launch-config 리튠)와 대조
- decode M≤8 대상 타일/launch-config 스윕 프로브를 `probes/`에 작성 (실측 shape 기반, 기존 하니스 패턴)
- 스윕 승자가 나오면 `glm53_mhc_tilelang` 오버레이 모듈 신설 (manifest + preimage SHA-256, env 게이트 **기본 off** — 브래킷 채택 시 기본화)
- `mhc_fused`+`pre_big_fuse` 융합축(−89/step 천장 1.5%)은 소스 확인 후 가능 여부 판단

### 4. srv4 측정 런북 — `RUNBOOK_KERNEL_CAMPAIGN2.md` 신설
우선순위 순 (하나의 노브/재기동, base→cand→base 브래킷):
1. **b12x EP 첫 실측** (`ENABLE_EP=1`) — 전문가 읽기 41ms/66ms 스텝, 보드 최대 숫자. #115/#120-122로 구현 완료, 부팅만 남음. 중단 기준 명시
2. **custom_ops A/B** (`CUSTOM_OPS_AXIS=""`) — #116으로 플럼핑 수정 완료, 유효 A/B 미실행. 천장 3.9%. 코드 0
3. **bproj 암** (항목 2의 새 게이트)
4. **mhc 암** (항목 3의 스윕 승자, 있는 경우)
- 공통 게이트: 품질 9/9 + 한국어 0/16 + C=1 step/s (CV 1.7%), 판정은 engine-confirmed 값
- apply는 사람 실행(RUNBOOK 법칙), 자동화·진단은 읽기 전용
