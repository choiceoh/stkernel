# 추가 오라클 개선 탐구 — 2026-09-13

개발 판단을 흔드는 계산 두 곳을 수정했다. 실제 서빙 성능 개선을 측정한 결과는 아니다.

| 발견 | 영향 | 반영한 개선 |
|---|---|---|
| 서로 다른 K에 같은 평균 수락률 적용 | 뒤쪽 draft 토큰의 기여를 선형으로 늘려 계산 | 관측 prefix 합으로 기대 출력 계산; 미관측 위치는 범위 |
| 프리필 재보정에서 청크 크기를 전체 토큰 수처럼 사용하고 두 설명 변수를 합침 | 토큰당 비용이 음수가 되는 계수 생성 | 전체 토큰·청크 수를 분리한 회귀, 부분 청크 보존, 식별 불가능한 기록 거부 |

## K의 한계 가치

관측 누적 수락률을 `s_i`, 스텝당 기대 출력을 `E_K = 1 + Σ(i≤K) s_i`로 놓으면
K−1에서 K로 늘릴 때 스텝 시간 증가율이 `s_K / E_(K−1)`보다 작아야 이득이다.
동일 prefix 분포, 보너스 1토큰/행을 유지하는 시나리오이며 실제 K 간 수락률 비교는 아니다.

설명용 합성 분포 `[20,10,10,10,10,20,20]`은 100행에서 여섯 번째까지 모두 수락한 행이 20개다.
`E_5=4`, `E_6=4.2`이므로 허용 시간 증가는 5% 미만이다. 일곱 번째는 미관측이므로
누적 수락률 `[0,20%]`, `E_7=[4.2,4.4]` 범위만 식별된다. 이 범위는 표본 신뢰구간이 아니다.

```sh
python3 bench/storacle.py acceptance peek.jsonl --economics
python3 bench/storacle.py predict --base origin/main --acceptance-from peek.jsonl
```

소스 비교에서 관측 분포는 기준·후보와 지정 컨텍스트·폭에 이관하는 가정이다.
새 코드의 수락률이나 품질이 검증된 것으로 표시하지 않는다. 미계측 커널 비용도 그대로 남긴다.
