# ST 드래프트 GPTQ 후 반올림 재최적화 연구

> 그날의 조사 — **2026-09-13 의 조사다.** 그날 참이었던 것이고 유지되지 않는다 — 이후 무엇이 바뀌었는지는 `MEASUREMENTS.md` 가 안다.

2026-09-13, 코드와 1차 문헌 검토. 프로덕션 패커·커널 변경이나 GPU 실행은
없다. 결론은 **기술적으로 가능하지만, 현재 GPTQ보다 나은지는 미확인**이다.
INT4 AdaRound를 그대로 붙이기보다 ST가 실제로 읽는 FP4→FP8 값과 A8 입력을
대상으로, 현재 GPTQ 팩에서 출발하는 제한된 재구성 실험이 적합하다.

## 현재 코드가 이미 하는 것

- `engine/kernels/dense/packing.py::_w4_gptq_codes`는 입력 Hessian을 사용해
  한 열의 양자화 오차를 아직 처리하지 않은 열로 전달한다. 단순 최근접
  반올림을 대체하는 단계는 이미 있다. Hessian 대각선 순서와 고정 16열
  그룹을 사용하며, 넓은 FC를 W4로 준비할 때에는 전체 K의 상관관계도 다룬다.
- `_E2M1_GRID`의 크기는 `0, .5, 1, 1.5, 2, 3, 4, 6`이다. 실제 가중치는
  부호를 붙인 이 값에 그룹 스케일을 곱하고 **E4M3로 다시 반올림한 후**
  행 스케일을 복원한다. `mk_w4_dequant_rowmajor`가 그 의미를 구현한다.
- W4 실행 입력은 `_mk_quant_x_ref`의 128열별 A8 반올림을 거친다. 입력은
  BF16이라고 해서 양자화 오차가 없는 것이 아니다. FP8 레인의 UE8M0
  스케일 규칙과 W4 레인의 activation scale도 서로 다르다.
- 기본 FC는 FP8이다. 따라서 FP4 재최적화의 첫 대상은 FC가 아니라 실제
  W4로 실행되는 드래프트 `self_attn.qkv` 또는 `mlp.gate_up`이다. 앞서
  도입한 smoothing alpha·GPTQ damping 탐색도 비교 기준에 포함해야 한다.

## 선행 연구와 적용 범위

[AdaRound, ICML 2020](https://arxiv.org/abs/2004.10568)는 레이어 재구성 오차와
연속 완화를 이용해 가중치의 올림·내림 결정을 최적화한다. 주된 결과는 CNN의
정수 양자화이므로, ST의 GPTQ FP4나 DFlash 수용률 개선을 입증한 논문은 아니다.

[GPTQ, ICLR 2023](https://arxiv.org/abs/2210.17323)는 근사 2차 정보를 사용한
언어 모델의 사후 양자화를 다룬다. ST에도 이 방식의 오차 전달이 있으므로
비교 대상은 RTNE가 아니라 **현재 준비 설정으로 만든 GPTQ 팩**이어야 한다.

[FP4DiT, 2025, §3.2](https://arxiv.org/html/2503.15465v1#S3.SS2)는 부동소수점
격자에서 기존 AdaRound를 적용할 때 간격에 따른 최적화 문제가 생길 수 있음을
분석하고 scale-aware AdaRound를 제안한다. FP 계열에서도 반올림 최적화가
가능하다는 직접적인 사례지만, 대상은 이미지 diffusion transformer이다.
논문의 혼합 FP 형식·활성화 방식까지 가져오면 ST의 현행 커널을 유지한다는
조건을 벗어난다. 여기서는 **불균일한 실제 격자 간격을 고려해야 한다는 원리**만
적용 후보로 삼는다.

## 제안하는 최소 실험

아래는 논문의 성능 결론이 아니라, 현재 ST 코드에 맞춘 설계 제안이다.

1. 드래프트 레이어 하나의 실제 BF16 입력과 원본 출력을 저장한다. 요청
   가족 단위로 준비·선택·최종 검증 데이터를 분리하고, 문맥 길이와 초반/후반
   드래프트 위치를 기록한다. 같은 요청의 이웃 토큰을 서로 다른 분할에 넣지 않는다.
2. 기존 smoothing·damping을 적용한 **현재 GPTQ 결과**를 기준으로 삼는다.
   그룹 스케일, 행 스케일, 패딩, 타일 순서는 고정한다.
3. 현재 nibble의 인접 표현값과 현재 값 자체를 후보로 둔다. 원본 가중치의
   양옆 두 값만 강제하면 GPTQ가 보상 과정에서 선택한 값을 잃을 수 있다.
   모든 후보는 ST의 E4M3 확장까지 통과한 실효 값으로 비교한다.
4. 입력도 실제 A8 기준으로 만든다. 목적 함수는 우선
   `|| BF16(Q_A8(X) · W_effectiveᵀ) − Y_BF16_reference ||²`로 둔다.
   연속 완화나 STE를 쓰더라도 최종 판정은 실제 nibble로 되돌린 후 한다.
   단일 레이어의 오차 감소가 드래프트 블록 출력에서도 유지되는지 별도로 본다.
5. 검증이 개선되지 않으면 원래 GPTQ 바이트를 그대로 돌려준다. 후보를
   채택할 때에는 데이터·기준 팩·알고리즘·설정 식별자를 캐시 키에 포함한다.
   현재 `PackStore.algorithm`은 패커 소스를 해시하므로, 별도 최적화 결과를
   기존 GPTQ 캐시에 덮어쓰면 안 된다.

처음부터 전 드래프트를 미세조정할 필요는 없다. 같은 출력 형식을 유지하는
레이어 한 개의 효과가 먼저 확인되어야 한다. 수용률은 후속 실험에서
candidate-miss와 selector-miss를 구분해 보고, 고정 K와 동일한 생성 조건에서
실제 출력 tok/s·응답 품질까지 함께 평가해야 한다.

## 비용의 범위

TP4의 현재 drafter shape에서 산술적으로 계산한 준비 메모리다. Adam 계열의
FP32 반올림 변수·gradient·두 moment를 모두 둘 경우에만 해당하며, 원본 가중치,
입력/출력, 작업 버퍼, 자동미분 저장은 **포함하지 않는다**.

| 대상 | 랭크당 가중치 수 | 위 네 FP32 배열만의 용량 |
|---|---:|---:|
| QKV, 1536 × 4096 | 6,291,456 | 96 MiB |
| gate/up, 6144 × 4096 | 25,165,824 | 384 MiB |
| 출력 128행 × 입력 4096열 작업 조각 | 524,288 | 8 MiB |

출력 행 단위 재구성은 준비 메모리를 줄일 수 있지만, 전체 블록의 상호작용을
그대로 최적화하는 것과는 다르다. 준비 시간과 메모리에는 비용이 있다.
반면 결과를 기존 nibble·스케일 형식으로 저장하면 **추론의 가중치 크기,
행렬곱 수, 커널 호출 수를 늘릴 필요는 없다**. 실제 지연시간이 동일한지는
실행으로 확인해야 한다.

현재 판단: **소규모 오프라인 연구를 할 근거는 충분하고, 기본 패커를 바꿀
근거는 아직 없다.** 실물 입력·가중치 재구성 결과와 matched 수용률 결과는
이번 조사에 없다. GPU 큐를 사용하거나 실험을 등록하지 않았다.
