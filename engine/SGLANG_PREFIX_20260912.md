# SGLang 의 접두사 캐시 블록 수명 — 조사 (2026-09-12)

`sgl-project/sglang` `e91c948` 의 `python/sglang/srt/mem_cache` 를 읽고 ST 와 대조했다. 범위는 원장 45차 §32 가 다룬
바로 그것 — **블록·상태의 수명, 축출 순서, 테넌트 분리** — 이고 그 밖은 안 봤다. 같은 날 다른 창이 같은 엔진의 **구조화
출력**을 대조했다(`SGLANG_COMPARISON_20260912.md`, 원장 §33); 겹치는 영역은 없다. **소스가 다르다**: 저쪽은 PyPI 휠
`0.5.19`, 여기는 GitHub `e91c948` — 이 파일들(`mamba_radix_cache.py`, `unified_radix_cache.py`, `evict_policy.py`)은
릴리스 휠보다 한참 앞서 있어서 휠로는 없는 얘기가 된다.

**결론부터**: vLLM 과 ST 는 "블록에 이름을 달아 자유 목록에 둔다" 는 같은 축에 있고, **SGLang 은 다른 축이다.**
수명 순서를 자유 목록에 넣지 않고 **라딕스 트리의 모양**이 대신하게 한다. 그리고 선형 어텐션 상태에 대해서는
**우리와 같은 결론에 독립적으로 도달했다** — 상태와 블록은 따로 축출하고, 상태만 잃은 노드가 남는다.

## 1. 세 엔진의 같은 질문, 다른 답

| | vLLM | SGLang | ST (§32 이후) |
|---|---|---|---|
| 재사용 단위 | 블록(해시) | 라딕스 트리 노드 | 경계(블록 사슬) |
| 해제된 블록의 정체성 | free 큐에 해시를 단 채 | 트리 노드가 계속 들고 있음 | 자유 목록에 이름과 등급을 단 채 |
| **자유 목록 순서** | 재사용 가치 (해시 없는 것 먼저, 꼬리 먼저) | **페이지 번호 오름차순** (주소 지역성) | 재사용 가치 (등급 넷) |
| 꼬리부터 축출 | `free` 때 reversed | **리프만 축출 가능** — 트리가 강제 | 꼬리부터 반납 + 중첩 경계의 등급 |
| 핀 | 없음 | **있다** (`lock_ref`) | 없다 (claim) |
| 한 번에 얼마나 축출 | 블록 하나 | `while num_evicted < num_tokens` | 블록 하나 |
| 축출 정책 | 고정 | **플러그인 일곱** (`evict_policy.py`) | 고정 (등급 넷) |

**자유 목록 순서가 가장 큰 차이다.** SGLang 의 `free()` 는 해제된 페이지를 `release_pages` 에 쌓아 두고, 할당이
`free_pages` 만으로 모자랄 때에만 `merge_and_sort_free()` 로 합쳐 **번호순으로 정렬**한다(`allocator/base.py:126-133`,
`allocator/token.py:54-72`). 순서가 재사용 가치가 아니라 **주소**인 것은 `alloc_extend` 커널이 연속 페이지를 좋아하기
때문이고, 재사용 가치는 트리가 따로 맡는다. 우리 블록은 768 토큰 × DSA 레이어 전체라 커널이 블록 테이블로 읽는다 —
연속성 요구가 없으므로 **이건 안 가져온다**.

**핀은 뜻이 다르다.** SGLang 의 `lock_ref` 는 *지금 도는 요청이 그 노드를 쓴다*는 뜻이고(`inc_lock_ref` 가 루트까지
거슬러 올라가며 `evictable_size_` → `protected_size_`), 우리 `pool.refs`(행이 쥔 블록)에 해당한다. 우리가 §32 에서
버린 핀은 *캐시 항목이 블록을 쥐는* 핀이었고, SGLang 에는 애초에 그런 게 없다 — 트리 노드가 값을 들고 있는 것으로 족하다.

**헛축출은 양쪽 다 구조적으로 불가능하다.** `evict()` 는 `evictable_leaves` 만 후보로 두고, 리프를 지우면 부모가 리프가
되어 힙에 들어간다(`radix_cache.py:616-643`). 짧은 경계는 **리프가 아니라서** 애초에 후보가 아니다 — 우리 옛 코드가
1 블록 얻으려 96 경계를 파괴하던 병리(§32)가 트리에서는 표현 불가능하다. 우리는 같은 성질을 등급으로 얻었다.

## 2. 선형 어텐션 상태 — 우리와 같은 문제, 거의 같은 답

`mamba_radix_cache.py` 는 우리 §32 가 푼 것과 **정확히 같은 문제**를 푼다: 블록은 흔하고 상태는 희소하다.

- 노드가 값을 **둘** 든다: `value`(full KV = 우리 블록), `mamba_value`(선형 상태 = 우리 스냅샷).
- 락도 둘, **LRU 리스트도 둘**(`LRUList(mamba=True/False)`). 불변식: `full_lock_ref >= mamba_lock_ref` —
  *"mamba 가 잠겼으면 full 도 잠겨 있다"*(`:84-90`).
- **`evict_mamba` 는 리프가 아니어도 된다**(`:884`). 상태는 노드마다 하나라 부모와 공유하지 않기 때문. `evict_full` 은
  리프만. 우리도 같다 — 스냅샷은 `_victim` 이 아무 경계나 고르고, 블록은 등급 순서가 고른다.
- 상태만 버린 내부 노드는 **tombstone** 이 된다(`_tombstone_internal_node`: `node.mamba_value = None`, KV 는 그대로).
  **우리 "바랜(faded) 경계"와 같은 물건이다.**

**갈리는 곳 하나, 우리가 낫다.** SGLang 의 tombstone 은 **부활하지 않는다** — `_match_prefix_helper` 가
`if node.mamba_value is not None` 일 때만 후보로 삼으므로(`:1123-1125`), tombstone 은 *더 긴 자손 노드로 가는 길목의
KV 를 살려 두는 표식*일 뿐이고, 리프가 되면 지운다(`_iteratively_delete_tombstone_leaf`). 우리 바랜 경계는 **티어에
상태 사본이 있으므로 스냅샷만 읽어 되살아난다**(§32: 128K 경계에서 ~1 GB → 45 MiB — 스냅샷은 KDA 상태 35.2 MiB + 샤딩된 드래프터 링 10 MiB). 같은 자료구조에서 우리가 한 발 더 갔다.

## 3. 테넌트 — 셋 다 다른 자리에 넣었다

| | 넣는 자리 | 티어/원격까지 |
|---|---|---|
| vLLM | 첫 블록 해시의 `extra_keys` | 해시에 들어가니 따라감 |
| SGLang | **`RadixKey` 의 별도 필드**, 해시에 안 섞음 | **계약 밖이라고 명시** |
| ST | 위치 0 의 솔트 → 첫 블록 해시 | 티어 키가 그 해시라 따라감 |

SGLang 은 `cache_salt` 를 해시에 섞지 않고 키 필드로 두고, **`_check_compatible` 이 솔트가 다른 키끼리의 연산 자체를
`ValueError` 로 막는다**(`radix_cache.py:169-180`). 실수로 섞이면 조용히 틀리는 게 아니라 터진다 — 좋은 방어지만,
해시에 섞는 쪽은 애초에 안 맞으므로 우리에겐 불필요하다.

`extra_key` 와 `cache_salt` 를 **필드 둘로 나눈** 이유가 주석에 있다: *"kept distinct so it cannot collide with
extra_key"*. 우리도 같은 걱정을 했고(위치 0 에 미디어 다이제스트가 설 수 있다), 필드 대신 `b"tenant:"` 태그로 막았다.

**그리고 저들이 스스로 적어 둔 구멍**: *"external L3/remote storage keys remain token-only and are outside this
contract"* — 원격 KV 스토리지 키는 토큰만으로 만들어져 **테넌트 분리가 안 된다**. 우리 접두사 티어는 키가 솔트 섞인
해시의 앞 56 비트라(`runner.tier_key`) 디스크까지 분리된다.

## 4. 가져올 것 — 하나

**`full_lock_ref >= mamba_lock_ref` 같은 명시적 불변식.** SGLang 은 "상태가 잠겼으면 그 KV 도 잠겨 있다"를 주석과
`sanity_check` 로 못박는다. 우리 대응은 *"바랜 경계의 블록이 살아 있지 않으면 그 경계는 아무것도 아니다"* 이고,
지금은 `_forget` 이 그렇게 동작할 뿐 **어디에도 단언으로 적혀 있지 않다**. 블록을 내주는 경로가 `forget_block` 하나뿐이라
지금은 맞지만, 두 번째 경로가 생기는 날 조용히 깨진다.

## 5. 안 가져올 것

- **자유 목록 번호 정렬**(1 참조) — 우리 커널은 연속 페이지를 요구하지 않는다.
- **축출 정책 플러그인 일곱** — 우리 `_victim` 의 (핀·adopt 여부·티어 사본·LRU) 는 저들 `SLRUStrategy`
  (`hit_count >= threshold` 로 보호 세그먼트를 가름)의 하드코딩판이고, **이미 같은 것**이다. 파라미터로 여는 건 D11
  (노브는 실험용이고 만료된다)에 어긋난다.
- **`lock_ref`** — 우리 `pool.refs` 가 같은 일을 이미 한다.
