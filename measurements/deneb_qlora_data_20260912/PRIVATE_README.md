# 데네브 QLoRA 자료 묶음 — 2026-09-12

이 자료는 srv4의 데네브 프로덕션 기록을 읽기 전용으로 가공한 비공개 데이터셋입니다.
다른 모델에서도 사용할 수 있는 입력·정답 JSONL과, GLM-5.3용 토큰 검증 결과를 함께 제공합니다.
모델 학습이나 프로덕션 변경은 수행하지 않았습니다.

## 어느 파일을 사용하는가

- `pool/pool.jsonl`: 중복 제거 후 7,152건. 메일 3,617건, 알림 3,035건, 대화 500건입니다.
  54건은 격리되어 있으며 나머지 7,098건도 모두 검증된 정답을 가진 것은 아닙니다.
- `sft/train.jsonl`, `validation.jsonl`, `test.jsonl`: 원문을 읽고 어시스턴트가 목표 응답을
  작성·검토한 48건(32/8/8)입니다. 메일·알림 각 24건입니다. 사람 검수는 수행하지 않았습니다.
- `sft/annotations.jsonl`: 원문 해시, 라벨 작성자와 검토 상태, 근거 인용을 보존합니다.
- `tokens-glm53/*.jsonl`: 동봉한 GLM 토크나이저·템플릿으로 만든 토큰과 `labels`입니다.
  입력은 `-100`으로 마스킹하고 응답 및 EOS에만 손실을 적용합니다.
- `review-queue.jsonl`: 추가 라벨 작성·검토가 필요한 후보의 색인입니다. 원문은 pool의 ID로 찾습니다.
- `pool/tool-corrections-review.jsonl`: 실패→성공 도구 재시도 11건입니다. 원본 수집기가
  인자를 300자로 잘라 저장하므로 도구 학습 정답이나 DPO 선호쌍으로 자동 승격하지 않았습니다.
- `quality-report.json`, `audit.ipynb`: 재실행 가능한 품질 검사와 집계 결과입니다.
- `model-metadata/`: 토크나이저·채팅 템플릿만 포함합니다. 모델 가중치는 포함하지 않습니다.
- `tools/probes/`: 추출, 검토 응답 내보내기, 토큰화, 품질 검사를 재현할 코드입니다.

## 정답의 의미

이번 SFT 묶음의 과제는 **제공된 메일·알림 텍스트만 보고 업무를 분류하는 것**입니다.
원래 데네브의 전체 시스템 지침·검색 결과·도구 상태를 재현하는 에이전트 학습셋은 아닙니다.
출력은 요약, `act/review/inform/ignore`, 제안 행동, 원문 기한 표현, 근거 인용,
부족한 문맥을 담은 JSON입니다. 실제 알림 발송·결재·메일 회신은 실행하지 않습니다.

`assistant_reviewed_source_grounded`는 현재 작업의 어시스턴트가 원문을 읽어 작성하고
검토했다는 뜻입니다. **사람이 확인한 gold 정답이 아닙니다.** 자동 검사는 인용이 실제 원문에
존재하고 기한 표현이 임의 변경되지 않았는지 확인하며, 판단 내용 전체의 정답성을 증명하지 않습니다.
과거 프로덕션 응답이 연결된 1,015건은 `production_unreviewed` 상태로 pool에만 보존합니다.
실행 로그의 `proactive=true`는 실행 유형이며 알림 가치의 정답으로 사용하지 않았습니다.

## 학습과 평가

48건은 형식·학습 파이프라인 검증과 후속 라벨링의 기준을 만드는 초기 묶음입니다.
현재 수량으로 본학습 효과나 전체 업무 성능 개선을 보장하지 않습니다.
메일 스레드·알림 출처·대화 세션의 기존 분할을 보존했고, 긴 동일 문장이 분할을 넘나드는
사례는 보수적으로 격리했습니다. 의미가 같은 모든 재서술까지 탐지한 것은 아닙니다.
알림 출처 전체를 같은 분할에 두었으므로 후보 풀의 분할 크기와 업무 분포는 균등하지 않습니다.

`test`는 과거 자료로 만든 **개발 평가 분할**입니다. 기존 분할이 앞선 분석에 노출되었고
이번 라벨도 어시스턴트가 확인했으므로, 최종 모델 비교에는 이후 시점의 새 평가 자료가 필요합니다.
기존 `wiki-qa-gold*.jsonl` 평가 파일은 수집 대상으로 삼지 않았습니다.

다른 모델에는 `sft/*.jsonl`의 `prompt`와 `completion`을 해당 모델의 채팅 템플릿으로
다시 토큰화하세요. Hugging Face TRL에서는 prompt-completion 데이터에
`completion_only_loss=True`를 사용합니다. 문자열 전체를 단순 언어모델링 데이터로 바꾸면
입력 메일까지 정답으로 학습하게 되므로 마스크를 확인해야 합니다.

동봉한 GLM 토큰 파일은 지정된 메타데이터 해시에만 유효합니다. 4,096토큰 한도에서
48건 모두 정답 잘림 없이 통과했고 최장 시퀀스는 1,844토큰입니다.
GLM 템플릿의 빈 reasoning 종료 표시와 EOS를 유지했습니다. 실제 SFTTrainer, QLoRA 역전파,
NVFP4 학습 또는 ST 어댑터 로딩의 호환성을 검증한 것은 아닙니다.

## 재검사

번들 디렉터리에서 다음 명령을 실행합니다. 품질 검사는 표준 Python만 사용합니다.

```sh
PYTHONPATH=tools python3 -m probes.deneb_qlora_audit .
sha256sum -c SHA256SUMS
```

토큰 검사를 새 디렉터리에 재생성하려면 `tokenizers==0.23.1`, `jinja2==3.1.6` 환경에서:

```sh
PYTHONPATH=tools python3 -m probes.deneb_qlora_tokenize \
  --sft sft --pool pool --metadata model-metadata \
  --out /새로운/비공개/토큰출력 --max-length 4096
```

## 출처와 비공개 처리

source inventory에는 읽은 파일 범위·바이트 수·SHA-256이 기록되어 있습니다. 원본은 살아 있는
저장소이므로 이후 다시 추출하면 내용과 수량이 달라질 수 있습니다. 원문의 이메일·휴대폰은
동일 대상을 식별할 수 있는 가명으로 바꾸고, 자격증명·URL 토큰·명시적 OTP 패턴을 가렸습니다.
업무 내용과 이름 등이 남아 있으므로 익명·공개 데이터가 아닙니다. 폴더는 0700, 파일은 0600으로
보관합니다. 가명화 키와 출처도 비공개 번들 내부에서만 취급하세요.

원본의 첨부파일·일부 알림 미리보기·빠진 검색 문맥을 복원했다고 주장하지 않습니다.
일부 자료에 잘린 미리보기 표시가 남아 있으면 검토용 플래그를 유지합니다. 자체점검 알림,
문자 손상, 분할 간 동일 내용은 격리됩니다. 생각 과정 블록·도구 실행 기록은 일반 대화
정답에서 제외했습니다. 불완전한 도구 문맥을 과거 답변과 임의로 연결하지 않았습니다.
