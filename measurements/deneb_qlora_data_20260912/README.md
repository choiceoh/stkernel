## 개선 내용

- 원본 메일 3,632건, 알림 원장 3,382건, 알림 판단 시작 로그 5,237건과 실제 사용자
  대화 135파일의 8,686레코드를 조사했습니다. 중복된 사건·반복 기록은 위 합계에서 제거했습니다.
- 메일 분석 문서는 파일 ID로 원문과 연결합니다. 선택적 `## 분석` 제목이 없는 문서도
  YAML·출처 메타데이터 다음의 본문을 읽도록 해 515건을 복원했습니다.
- 대화는 사용자 입력 뒤의 완결된 텍스트 응답만 연결합니다. 생각 과정과 도구 문맥이
  누락된 실행은 일반 대화 정답으로 자동 변환하지 않았습니다.
- 알림의 `proactive=true`를 정답 라벨로 해석하지 않았습니다. 실제 실행 유형을 나타내는 값입니다.
- 이메일·휴대폰은 같은 대상을 구분할 수 있는 가명으로 바꿨습니다. 한글에 붙은 주소와
  서로 붙은 주소, URL 토큰, OTP 패턴도 처리했습니다. 업무 내용과 이름은 남아 있어 비공개 자료입니다.
- 기존 메일 스레드·알림 출처·대화 세션 분할을 유지했습니다. 정확한 중복, 분할 사이의
  긴 동일 문장, 자체점검 메시지와 문자 손상을 검사했습니다. 기존 QA 평가 파일 11개는 수집에서 제외했습니다.
- SFT 응답은 요약·판단·행동·기한·근거·부족한 문맥을 명시합니다. 미확정 일정, 첨부파일
  부재, 인용된 과거 요청과 예시 금액을 확정 사실로 만들지 않도록 원문을 검토했습니다.
- `prompt/completion` 형식과 입력 `-100` 마스크를 제공합니다. GLM 템플릿의 빈 reasoning
  종료 표시와 EOS를 유지하고, 토큰화 후 응답을 원래 문자열로 되돌려 비교했습니다.

## 검증과 한계

[품질 검사](quality-report.json)에서 분할 간 그룹 중복 0건, 잔여 이메일 정규식 탐지 0건,
근거 인용 117개 일치, SFT 마스크 정상, 정답 잘림 0건을 확인했습니다.
12개 [단위 테스트](tests.log), Python 구문 검사와 diff 검사가 통과했습니다.
[최종 파일 검사](final-verification.json)는 32개 파일의 해시와 비공개 권한을 확인했고,
압축파일의 모든 내용을 다시 읽어 원본 파일과 비교했습니다. [노트북](audit.ipynb) 코드 셀도 실행했습니다.

[토큰 검사](tokenization-report.json)는 원본 NVIDIA 체크포인트의 메타데이터 해시를 고정했습니다.
초기 48건은 407–1,844토큰으로 4,096 한도에 모두 들어갑니다. 전체 후보 풀의 대화 19건은
입력만으로 4,096토큰을 넘고, 3건은 8,192토큰을 넘습니다. 이 긴 문맥은 잘라 저장하지 않았습니다.
다른 모델에는 portable SFT 파일을 다시 토큰화해야 합니다.

메일 자료는 2016년부터 2026년까지 섞여 있고, 알림은 2026년 6월 이후, 대화는 3월 이후입니다.
출처 단위의 엄격한 분할로 알림 검증 후보가 많고, 대화 개발 평가 후보는 6건으로 적습니다.
현 분할은 개발용이며, 이후 시점에 수집한 별도 자료 없이는 최종 모델 성능을 주장할 수 없습니다.
48건은 학습 흐름·출력 계약을 검증하기 위한 시작점이며 본학습 효과를 보장하는 규모가 아닙니다.
원문 인용 검사가 의미적 정답성까지 증명하지는 않습니다. 과거 응답 1,015건도 검수가 필요합니다.

실제 SFTTrainer 실행·QLoRA 역전파·NVFP4 학습·ST 어댑터 로딩은 검증 범위 밖입니다.
입력과 정답 분리는 [TRL 공식 prompt-completion 규칙](https://huggingface.co/docs/trl/sft_trainer#train-on-completion-only)을 따릅니다.
비공개 번들의 상세 사용법은 [동봉 README 원본](PRIVATE_README.md)에 있습니다.
