## 5. 사전 컴파일 — 기록은 됐고, micro 키는 어긋났다 (고침)

부팅 1 이 노드마다 요청 8~11 개를 기록했다(`~/glm53-cache/cu132/st-b12x-requests/qwen38.jsonl`). 창 뒤 `start-st-qwen38.sh prebuild`:
네 노드 모두 요청 10~12, **적중 4~7 · 재사용 1~2 · 새로 빌드 4**. dynamic 커널은 GPU 부팅의 이름 그대로 적중했지만 **micro 커널 4 개는 다른
해시로 빌드됐다**(GPU `micro_m8_…_875f80d35b4461fc` 대 재생 `…_48938cdd0a422246`). 원인: 디스패처가 micro 의 타일·scatter 를 묶인 커널
형상의 MoE 셀에서 고르는데(`moe_dispatch._admitted_moe` → `kernel_shape.bound()`), 재생 프로세스엔 형상이 묶여 있지 않아 GLM-5.3 의
측정 셀(E288·I512·top8)로 골랐다. 수정: 기록에 묶인 형상을 넣고 재생이 요청마다 그 형상을 건다. CPU 에서 Qwen 형상을 묶고 같은 요청을
부르면 이름이 **GPU 플릿 부팅과 같은 `875f80d35b4461fc`** 다; 형상을 빼면 테스트가 정확히 이 불일치로 실패한다.
기존 기록 줄(형상 없음)은 읽지 않는다 — 다음 부팅이 형상과 함께 다시 기록한다.
