## 고친 것 (자체 경로)

- **프리필**: `select_sm120_moe_backend` 에 규칙 하나 — expert-local 즉시 프리필(한 행에 한 라우트, 모든 전문가가 로컬, 디코드
  스텝(8 행)보다 많은 행)은 b12x 의 **dynamic 프리필 커널**로. 아티팩트 이름이 `dynamic_e128_k2560_n640_t1_<key>` 로 행 수와
  무관하다(정적 커널은 `static_m{행}_…_r{용량}` 으로 행마다 하나). 이번 부팅 랭크 0 의 CuTe-DSL 컴파일: **2 개**(첫 창 75 개).
- **one-shot**: 고칠 것이 없었다. 창 2 에서 기본(one-shot RDMA, inline flags)으로 STALL 0 — 창 1 의 스톨은 피어들이 커널을
  컴파일하느라 늦어 생긴 증상이었다(NCCL 로도 같은 스텝이 같은 시간 걸렸다). `--no-oneshot`(`ST_ONESHOT=0`) 은 옵션으로 남긴다.

## C4 프로브 (srv4, `ST_PROBE_CHECKS_ONLY=1`, `moe-checks-srv4.jsonl`)

합성 전문가 128개(프리샤드와 같은 NVFP4 인코딩), 서빙 라우터의 라우트. 오라클 = `engine/modules/moe.expert_gemm` 의 데이터플로
(reciprocal quantiser), 문턱 2%.

|---|---|---|---|---|---|

| prefill 16 토큰 | 43 | dynamic | 16 | 0.0080 | 불안정: ±1 bf16 ulp 급(max_abs 2^-7), 상대 0.011 |
| prefill 64 | 156 | dynamic | 16 | 0.0069 | 불안정 0.0034 |
| prefill 128 | 339 | dynamic | 16 | 0.0089 | 불안정 0.0045 |
| prefill 1024 | 2,563 | dynamic | 32 | 0.0054 | 불안정 0.0054 |
| prefill 4096 | 10,239 | dynamic | 64 | 0.0074 | 불안정 0.0074 |

전부 오라클 안. 프리필의 반복 불안정은 dynamic 커널의 BF16 원자 scatter 순서(GLM 프리필도 같은 커널)로, 프로브가 "기록하는 발견,
멈춤 아님" 으로 두는 것. 정적 프리필의 반복 불일치(첫 C4 실행)와 달리 오라클은 매번 든다.

## 창 3 — MTP 체인 K=3 (17:34~17:47, 운영자 "k=3 정도 하지" → "k=3가 안되면 k=2까지만해", PR #1182)

`fleet --spec-k 3`(launcher `ST_SPEC_K=3`): 드래프트 재생 하나 안에서 MTP 헤드를 세 번 — 관측 스텝(검증 폭 4 로 패딩) 뒤 체인
두 런치(행마다 한 위치; 직전 pick 이 그 위치의 토큰, 헤드 자신의 streams 가 상태; `decode_graphs.draft_chain`). 검증 스텝은 행당
4 토큰. 이미지 `st-engine:qwen38` 은 창 밖에서 다시 빌드(캐시 레이어).

| 부팅 | 행 | 결과 |
|---|---|---|
| K=3, 기본 4 행 | 4 | 캡처에서 죽음. (3 행 × 4 토큰) 타깃 워밍업에서, 방금 컴파일한 정적 MoE 커널 `static_m12_k2560_n640_t10_r160` 의 첫 런치 직후 `illegal memory access`(다음 QSA 런치의 Triton `load_binary` 에서 드러남; 네 랭크 모두). 4 행 × 4 = 16 토큰의 `static_m16` 은 컴파일·워밍업·캡처를 지났다. 12 토큰은 micro 상한 8 을 넘어 정적 커널로 가는데 Qwen 이 처음 밟는 모양 — 격리는 단일 GPU 레인(C4 프로브에 디코드 12/16 토큰 검사) |

450 토큰 요청 둘: 토큰/스텝 **+44% / +36%**, 스텝 시간 **+28% / +25%**, 디코드 tok/s **+12.5% / +9.6%**, 프리필 포함 tok/s
**+17% / +13%**. 드래프트 슬롯당 수용은 K=1 69~71%(265 중 183·184), K=3 46~48%(554 중 264, 580 중 255 — 세 자리 평균). 둘째 바퀴
합계: K=1 1,308 스텝·2,249 토큰(1.72/스텝, 34.7 ms), K=3 938 스텝·2,252 토큰(2.40/스텝; 평균 74.7 ms 는 아래 콜드 컴파일 포함).

콜드 비용(K=3 만): 요청이 끝나 행이 파킹되면 드래프터는 대기 중인 관측 행을 **즉시 헤드**로 돌린다 — 파킹된 행의 예약은 지킨 위치까지라
체인 위치를 덮지 않아 재생을 못 쓴다(`adapter.ServedMTP._run_waiting`). 그 즉시 경로의 MoE 는 (행 수, 용량) 조합마다 `micro_m{1..4}_…_t1_r{3,4}`
아티팩트를 한 번 컴파일(랭크마다 4~5 s): 첫 바퀴의 550~650 ms/스텝 평균과 둘째 바퀴 앞 두 요청(175, 83.5 ms/스텝)이 그것이고,
`/cache` 에 남는다. one-shot STALL 0, 오류 0(네 랭크).

K=2 는 폴백이 아니다: 3 행 × 3 = 9 토큰이 같은 정적 경로(micro 상한 8 초과)를 밟는다. 2 행이면 3·6 토큰이라 micro 다. 4 행은 정적
커널 m12 격리 뒤에.

## 안 잰 것

C=2/4(짝), T=1 수용률, 긴 컨텍스트(≥8K), K=2/4, one-shot 지연 실측(`ONESHOT_MEASURED_HIDDEN` 기록은 별도 프로브), 프리필의 SSD PLE
모음 비용 분리, 정확도 벤치. 콜드 JIT 은 `/cache` 에 남아 다음 부팅부터 사라진다.
