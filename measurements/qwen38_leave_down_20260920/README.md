## 무엇을 시도했나

`gated_residual.leave_down_block` / `_leave_down_rows`: 프로그램 하나가 (행 블록, 줄기 하나)를 맡아 ① 서브레이어 출력을 그 줄기에 더하고 제곱합을 모아
스케일을 쓰고(`stream_scales` 의 산술, BLOCK_K 씩), ② 방금 쓴 행을 L2 에서 다시 읽어 **한 번** 정규화한 뒤 그 줄기의 K 조각을 다운(+주입)의 **모든 열 블록**
(64 폭 다섯 개 + 16 폭 꼬리)에 동시에 곱하고, ③ 줄기별 fp32 부분합을 스크래치에 두고 행 블록의 마지막 프로그램이 줄기 순서로 더해 게이트를 저장한다.
기대: 줄기를 DRAM 에서 두 번이 아니라 한 번 읽고(84 MB), A 타일 변환을 열 블록마다가 아니라 한 번 하고, MMA 가 leave 의 메모리 시간과 겹친다.

- 정확성은 전부 통과(24 칸): leave 뒤 줄기는 두 발사와 **바이트 동일**, 스케일 최대 상대 오차 2.2~3.5e-7(제곱합의 결합 순서), mixed 는 두 발사 대비 최대
  0.34~0.40%(다른 원소 0.1~0.2%), torch 형태 대비 0.34~0.40% — 두 발사 자체가 torch 대비 0.34~0.40% 인 것과 같은 거리.
- **가장 빠른 fused 도 두 발사보다 21% 느리다**(4,096 행 1,900 대 1,569). 이유(측정으로 읽은 것):
  - MMA 효율은 큰 BLOCK_M 이 필요하다(기존 다운은 256 행 블록으로 W 6.6 MB 를 16 번 읽음). 모든 열의 누산기를 한 프로그램에 두면 레지스터가 BLOCK_M 을
    32~64 로 묶고, W 를 64~128 번(425~850 MB) L2 에서 다시 읽는다. 64 행·8 warps 는 32 행·4 warps 보다 느렸다(스필로 보임).
  - leave 의 메모리 구간과 MMA 구간이 한 프로그램 안에서 직렬이고, 누산기 크기 때문에 SM 당 CTA 가 하나라 프로그램 사이의 겹침도 없다.
  - 128 폭 열 블록 셋(32,128,64)이 64 폭 여섯보다 빠르다 — 반복마다의 레이아웃 변환·B 타일 로드 수가 비용이다.
- 이론 상한을 다시 보면: leave 구간 ≈ 790 µs(대역폭) 는 그대로고 MMA 구간이 776 → 아무리 잘해도 ~500 이므로 fused 는 ≈ 1,300 이 바닥 — 지금 1,569 의 −17%
  이지만 그 바닥에 닿을 길이 Triton 에선 보이지 않는다(큰 BLOCK_M 과 SM 당 CTA 둘을 동시에 못 가짐).

A 변환을 한 번 하는 변형(776 → ~570 추정, 바이트 동일 가능성). up 접기(876 µs, 바닥 ~550)의 타일 스윕은 별도 기록.
