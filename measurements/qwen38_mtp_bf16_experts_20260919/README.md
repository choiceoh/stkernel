# Qwen3.8 MTP 전문가 — 원본 BF16 으로 고정 (2026-09-19, srv4 단일 GPU 레인)

> 그대로 두는 기록. 운영자: "원본 bf16으로 고정해", "원장에 엔진의 구현 목표는 기본은 nvfp4이되, 비용은 적고 수용률 영향 큰 부분은 투자한다로 해".

## 1. 실가중치 대조 `q38mtpx-0919b` ([원시](q38mtpx-0919b.json))

랭크 3 의 MTP 전문가, 실제 크기의 활성(σ 0.5) 행을 랭크의 전문가 열 개로 라우팅(가중치 합 1). 기준은 원본 BF16 을 torch 로 계산한 값(`moe_rows.reference`).

| 행 | BF16 커널 max / rms | FP8(export) max / rms | **NVFP4 재인코딩(지금까지 서빙)** max / rms |
|---:|---:|---:|---:|
| 1 | 0 / 0 | 0.048 / 0.045 | **0.222 / 0.232** |
| 4 | 0.0025 / 0.00015 | 0.048 / 0.046 | **0.263 / 0.229** |
| 16 | 0.0019 / 0.00016 | 0.040 / 0.046 | **0.212 / 0.232** |

- `moe_rows.qualify`(부팅의 D3) BF16·FP8 모두 GPU 에서 오차 0.
- **드래프터의 MoE 출력이 원본에서 RMS 23% 벗어나 있었다.** preshard 가 export 의 FP8 을 BF16 으로 풀었다가 교정 없이 NVFP4 로 다시 양자화했고(활성 전역 스케일
  1 고정), b12x 가 활성까지 FP4 로 양자화한다. export 의 FP8 자체는 4.5%.
- 사이드 파일: `mtp_side.py --precision bf16`, 예전 사본(srv2 `qwen38-flash-next-nvfp4`)의 fused BF16 전문가를 랭크 몫으로 잘라 랭크당 1,258,291,480 B
  ([manifest](mtp-bf16-manifest.json)), 네 노드 배포·해시 확인. FP8 사이드 파일과 전 전문가 상대 오차 0.0266 — 같은 가중치.
