## 1. MTP dense 정밀도 — 드래프트 그래프 비용 `q38mtp-0919a` ([원시](q38mtp-0919a.json))

단일 GPU 레인(srv4, 프로덕션 옆), 층 집합 [4,5] 빌드, K=3 드래프트 그래프(관측 1 + 체인 2) 재생 wall, µs. 이 티켓은 #1226 의 행 선택·rows_linear
**이전** 트리(f38bba79 위)로 돌았다 — 세 팔의 차이는 dense 네 투영(어텐션 in/o, 공유 전문가 gate_up/down)만.

| 팔 | 1 행·버킷 6 | 1 행·버킷 43 | 4 행·버킷 43 |
|---|---:|---:|---:|
| W4A8 (#1226 전) | 3970.6 | 4089.8 | 4472.3 |
| FP8 (fp8_rows) | 4101.0 | 4180.0 | 4553.3 |
| **BF16 (기본)** | **4387.8** | **4467.4** | **4748.5** |

- FP8 은 +0.13 ms(12 호출 49 MB, 대역폭 그대로), BF16 은 +0.42 ms(cuBLAS gemv·WMMA — 대역폭 아래). 운영자가 BF16 을 골랐다.
- BF16 은 #1226 에서 `lanes.rows_linear` 로 간다 — skinny GEMV 의 MTP 모양 타일은 아직 없어 torch.mm 과 같다(스윕 `q38gemv-0919e` 대기).

## 3. #1226 에 들어간 나머지 (전부 기본 끔, 행 선택만 기본 켬)

- **IVF 근사 헤드** (`dense/ivf_head`, `--draft-index C/P`): 가짜 쿼리 재현율·비용 티켓 `q38ivf-0919b` 대기. 실제 드래프트 쿼리는 이 PR 의 탭으로 창에서 뜬다.
- **MTP 전문가 FP8** (`--mtp-experts-dir`): 체크포인트(NVIDIA export)는 MTP 층 전문가만 **FP8 block-128** 로 두었는데 preshard 가 NVFP4 로 재인코딩했다(이중 양자화,
  활성 FP4). export 의 바이트 그대로의 사이드 파일(`mtp_fp8.py`, 랭크당 629,299,672 B, 읽어 되짚어 해시 확인 — [manifest](mtp-fp8-manifest.json)),
  `kernels/moe_fp8_rows`(W8A16, 인터프리터 qualify 0.010~0.014 — BF16 캐스트를 자르는 인터프리터 탓, GPU 미판정). **사이드 파일은 srv4 에만 있다.**
- **어텐션 뒤 행 선택** (`mtp_forward(rows=)`, 기본 켬): 드래프트 관측의 MoE 가 행의 마지막 위치만, 프롬프트 관측이 세그먼트 마지막 행만 돈다.
  GPU 동등성 검사(전 행 뒤 선택 대 선택 뒤 계산)는 `q38mtp-0919c` 대기 — **머지가 판정보다 먼저였다.**

  51~54 ms·2.51~2.68(다른 요청), 드래프트 수용 51.6%.
