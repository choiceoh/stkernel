# Qwen3.8 QSA covered 어텐션을 한 dot 에 쌓기 — 새 프롬프트 2,048 행 1,610 → 795 µs, 첫 청크 4,096 행 8,861 → 5,365 µs (2026-09-19)

srv4 단일 GPU 레인, 프로덕션 `st-qwen38` 옆, `--lanes qwen38_qsa_stacked`(`probes/engine_qwen38_qsa_geometry.run_stacked`). 체크포인트 없이 랭크 당 셀
(query 6 헤드 / KV 1 헤드 × 256, 예산 2,048 → 2,051 열, 블록 768)에 합성 K/V. **커널 컴포넌트 시간이다 — 엔진 tok/s 주장은 없다(헌장 D17).**

| 티켓 | 트리 | 내용 |
|---|---|---|
| `q38qsastack-0919a` | `8c0edda4` | 새 프롬프트(위치 0 부터) 256·512·1,024·2,048 행: run 발사(오늘) 대 stacked 발사 기하 여섯; 4,096 행 첫 청크: 전부 sparse 대 reach 에서 나눔 |

프로덕션이 요청을 받는 동안이라 중앙값이 흔들린다(256 행 run 발사 중앙 207 / 최소 96 µs) — **판정은 번갈아 돈 반복의 최솟값**으로 했다.

## 1. 새 프롬프트, 예산이 덮는 행 (µs, 최소 / 중앙)

| 행 | run 발사(오늘) | stacked 16·64·4 (**규칙**) | stacked 16·64·8 | stacked 32·64·8 | stacked 16·128·8 |
|---:|---:|---:|---:|---:|---:|
| 256 | 96 / 207 | 131 / 140 | 67 / 148 | 123 / 131 | 204 / 225 |
| 512 | 171 / 241 | **124** / 185 | 134 / 194 | 81 / 91 | 270 / 332 |
| 1,024 | 474 / 475 | **222** / 223 | 273 / 275 | 181 / 181 | 478 / 480 |
| 2,048 | 1,610 / 1,618 | **795** / 850 | 1,023 / 1,026 | 637 / 704 | 1,095 / 1,147 |

- 16 폭 타일은 **sparse 발사와 바이트 동일**(모든 행 수, 게이트 포함) — GB10 의 MMA 는 원소 하나의 K 를 M 과 상관없이 같은 순서로 더한다.
  인터프리터의 numpy matmul 은 그렇지 않아서 테스트는 인터프리터에서 밴드, GPU 에서 바이트를 본다.
- 32 폭은 2,048 행에서 20% 더 빠르지만 softmax 를 다른 자리에서 반올림한다(최대 0.0018, rms 0.0012 — 밴드 안). 바이트를 지키는 16·64·4 를 규칙으로.
- 64 폭·M 128×32 폭은 공유 메모리 초과(106,752 / 106,624 > 101,376 B)로 컴파일 거절.

## 2. 첫 청크가 reach(2,051)를 넘을 때 (4,096 행, 위치 0 부터)

| | 최소 | 중앙 |
|---|---:|---:|
| 전부 sparse(오늘) | 8,861 | 16,915 |
| 앞 2,051 행 stacked covered + 나머지 sparse | **5,365** | 10,447 |

출력은 전부 sparse 와 바이트 동일. 앞 행들은 원래도 보이는 모든 그룹을 골랐던 행이라(선택 = 전부) 결과가 같다.

## 추정 (측정 아님)

QSA 층 12 + MTP 헤드 1: 2,051 토큰 이하 프롬프트는 층당 약 −0.8 ms(2,048 행) → 약 −10 ms, 2,051 토큰을 넘는 프롬프트의 첫 청크는 층당 −3.5 ms →
약 −45 ms. 이후 청크(컨텍스트 ≥ 4,096)는 그대로. 플릿 onepass 는 재지 않았다.
