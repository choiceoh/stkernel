# ACE식 전문가 슬롯 스킵의 품질 — 한 부팅에서 코퍼스 다섯 번, 프리필 head NLL 짝 비교 (2026-09-17)

> 그날의 조사 — **2026-09-17 의 조사다.** 그날 참이었던 것이고 유지되지 않는다 — 이후 무엇이 바뀌었는지는 `MEASUREMENTS.md` 가 안다.

바이트 쪽(`measurements/st_ace_routes_20260917`)이 남긴 질문의 나머지 절반이다. **판정: 스킵 10% 는 토큰당 +0.02~0.03 nats 를 쓰고
그 대가는 스텝 상한 −4.5% 다.** 운영자가 옮기지 않았던 NVIDIA 랭크의 차이(+0.034)와 같은 크기라 기본값으로 올릴 근거가 없다.
디코드 수용률·step/s 는 재지 않았다.

## 방법 — 부팅 하나, 패스 다섯

- **노브(이 PR, 기본 꺼짐).** `Glm53Net.route_skip` 이 None 이 아니면 `_select_routes` 가 정규화 게이트가 임계값 아래인 슬롯의 가중치를
  0 으로 만들고(토큰의 1위는 유지) 남은 가중치를 `routed_scaling_factor` 로 재정규화한다. id 는 그대로라 커널은 중복 전문가를 보지 않고,
  수치는 슬롯을 건너뛴 것과 같다(바이트는 그대로 읽는다 — 품질 팔이라서). 디코드 캡처 그래프는 None 으로 만들어져 다시 읽지 않는다.
- **캡처 패스.** `capture.Capture(skip_passes, pass_documents)`: 문서 `[k·n, (k+1)·n)` 이 패스 k 이고, 프리필 forward 가 그 패스의 스킵을
  걸고 항상 지운다. head 채점 위치의 시드를 시퀀스 id 대신 `문서 % n` 으로 잡아 **모든 패스가 같은 위치를 채점**한다.
  피드는 패스마다 `--cache-salt` 를 달아 프리픽스 캐시를 피했다(패스 1 의 `cached_tokens` 합 0, 프롬프트 417,189 토큰 전부 프리필).
- **팔.** main `ffc8b664` + 노브 `424722a0` + 디버그 `4ff75add`(`EXPERT_CAPTURE = True`, 스케줄; `debug-ace-quality-arm-4ff75add.patch`,
  머지 안 함). 플릿 hold `aceq-0917`, 도어 09:53, 패스당 약 3 분, 10:09 종료(`runner.log`). Red Hat 랭크, 운영 레인.
- **패스.** 0 끔 · 1 전역 10%(τ 0.07012) · 2 전역 15%(τ 0.07679) · 3 층별 10%(42 개 τ, 같은 라우트 덤프의 층별 분위수) · 4 끔 반복.
  임계값은 C=1 디코드 라우트에서 뽑았고 프리필에 그대로 썼다.
- **비교.** `split_passes.py` 로 `head.jsonl`(srv4 캡처 랭크, 665 행, sha256 `5eb1653f…`)을 패스별로 나눠 문서 번호를 0 부터 다시
  매기고, srv2 의 `head_compare.py --a pass0 --b passK --feed feed/feed-pass0.jsonl` 로 짝지었다(`head_compare.log`).
  같은 위치·같은 타깃 토큰만 세고, 신뢰구간은 문서 부트스트랩이다.

## 읽기

- **측정은 충분히 조용하다.** 같은 부팅에서 같은 설정을 다시 먹이면 위치의 95% 가 비트 단위로 같고 평균 차이는 +0.001 이다.
  아래의 흔들림은 측정이 아니라 스킵 자체에서 온다.
- **스킵은 거의 모든 위치를 흔든다.** 스킵한 패스에서 같은 값인 위치는 0.5% 뿐이고, 위치의 약 45% 는 좋아지고 55% 는 나빠진다.
  문서별 평균 변화가 ±0.1~0.4 nats 로 퍼져서 평균의 신뢰구간이 넓다.
- **전역 10% 와 층별 10% 는 0 을 제외한다.** 대략 +0.02~0.03 nats 다. 논문의 Qwen3-30B 10%(+0.004)보다 크고 Qwen3.6(+0.021)과
  비슷하다 — GLM 의 평평한 게이트(스킵 10% 가 라우팅 질량 4.6% 를 뺀다)로 예상한 방향이다.
- **15% 가 10% 보다 작게 나온 것은 순서를 말하지 않는다.** 세 팔의 구간이 서로 겹친다. 이 코퍼스(133 문서)로는 팔 사이 순위를 못 가린다.
- **값어치.** 바이트 쪽 상한은 스킵 10% 에서 스텝 −4.5%, 15% 에서 −6.6% 이고 수용률 손실은 빼지 않은 값이다. 대가 +0.02~0.03 nats 는
  2026-09-14 에 운영자가 택하지 않은 NVIDIA 랭크의 +0.034 와 같은 크기다. 기본값으로 올릴 근거가 없고, 이 레버는 여기서 닫는다.

## 못 한 것

- 디코드 수용률·tokens/step·step/s·onepass 품질 게이트. 스킵은 타깃 분포를 바꾸므로 드래프터 수용률도 떨어질 것이지만 재지 않았다.
- ACE 의 GSP·RCR 전문가 표(게이트만의 대리 규칙을 썼다).
- 바이트를 실제로 줄이는 경로(스킵한 슬롯의 id 를 치우는 것)는 커널의 토큰당 전문가 비중복 불변식을 깨므로 만들지 않았다.
- 임계값은 디코드 라우트에서 뽑아 프리필에 썼다. 프리필 토큰의 실제 스킵 비율은 세지 않았다.
