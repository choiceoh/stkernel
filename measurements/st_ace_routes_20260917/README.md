# ACE식 전문가 슬롯 스킵이 C=1 검증 스텝의 전문가 읽기를 얼마나 줄이나 — 실제 라우트, main `a9bf7afc` (2026-09-17)

> 그날의 조사 — **2026-09-17 의 조사다.** 그날 참이었던 것이고 유지되지 않는다 — 이후 무엇이 바뀌었는지는 `MEASUREMENTS.md` 가 안다.

**판정이 아니다.** 스킵을 서빙하지 않았다. 품질·수용률·step/s 는 재지 않았다. 여기 있는 것은 실제 디코드 라우트를 오프라인으로
다시 센 **바이트 상한**이고, 품질 팔을 만들지 말지 정하는 재료다.

## 질문

논문 지도(`docs/PAPER_MAP_20260917.html` 10절)가 바이트를 줄이는 유일한 후보로 ACE(arXiv:2609.05228, 보정 없는 전문가 스킵)를
남겼다. ACE 는 토큰마다 1위 전문가를 남기고, 전역 임계값 아래의 라우팅 슬롯을 건너뛴다. GB10 디코드는 MoE 전문가 스트리밍이
스텝의 46% 인데, 8 검증 행이 전문가를 나눠 읽는다(#966: 64 슬롯에 층당 41.9 개). **슬롯을 건너뛰어도 다른 행이 같은 전문가를
읽으면 바이트는 줄지 않는다.** #966 의 원시 행은 층별 요약뿐이라 이 질문을 오프라인으로 다시 셀 수 없었다.

## 무엇을 어떻게 쟀나

- **트리.** main `a9bf7afc` 위에 디버그 커밋 `e52fb5cb` 하나(`debug-ace-route-dump-e52fb5cb.patch`, 머지하지 않는다). #966 의
  `ef2e5b6e` 와 같은 방식이다. 캡처된 디코드 그래프가 층마다 top-8 id·가중치를 정적 버퍼에 복사하고, 모든 스텝을 동기로 돌린다.
  rank 0 이 스텝마다 int16 id 와 float32 가중치 `[42 MoE 층, 8 행, 8]` 를 이진 파일에 붙이고, latency 행에 오프셋을 적는다.
- **조건.** Red Hat 랭크, 운영 env, 플릿 hold 한 번(`ace-routes-0917d`, 도어 06:22, 측정 06:22~06:30). onepass JSON 12 문항
  (`json-s100`~`s103` × ledger/portfolio/logic), C=1, 온도 0, thinking 켬 — #966 과 같은 부하다. 클라이언트 `ace_route_probe.py`,
  러너 `run_ace_hold.sh`, 출력 `client.log`.
- **원시.** 6,154 스텝, 99,251,712 B. 이진 파일은 커밋하지 않았다(srv2 `~/glm53-logs/route-dump/aceroutes-a72ff6afe743.bin`,
  sha256 `routes.sha256`). 행은 `rows.jsonl.gz`.
- **분석.** `python3 analyze_routes.py rows.jsonl routes.bin` → `summary-gate.txt`, `python3 analyze_detail.py rows.jsonl routes.bin`
  → `summary-detail.txt`. 규칙은 ACE 의 것이다. 토큰의 정규화 게이트(`w / sum(w)`)로 슬롯을 매기고, 1위는 항상 남기고, 1위가 아닌
  슬롯 전체의 분위수로 전역 임계값 하나를 정한다. ACE 의 GSP·RCR 전문가 표는 **곱하지 않았다**(게이트만의 대리 규칙). 표를 붙일
  자리는 `--table` 로 열어 두었다.
- **시간 환산.** 읽기 감소 × MoE 비중 0.458(PR #963 의 25.13/54.89 ms). MoE 시간이 고유 전문가 수에 비례하고 tokens/step 이
  그대로라는 가정의 **상한**이다. 스킵은 타깃 분포를 바꾸므로 수용률은 따로 재야 한다.

## 읽기

- **바이트 레버는 실재한다.** 스텝 상한이 스킵 비율의 약 0.45 배로 선형이다. 상한이 5% 를 넘는 지점은 스킵 약 11% 다.
- **결정은 품질이 한다.** 스킵 10~15% 가 GLM 에서 몇 nats 인지, 수용률(tokens/step)을 얼마나 깎는지가 전부다. 여기서 재지 않았다.
- **전역 임계값은 GLM 에 맞지 않을 수 있다.** 층 편차 2.7%~37.7% 는 몇몇 층의 라우팅을 크게 바꾼다는 뜻이다. ACE 의 층 정규화
  표(GSP·RCR)나 층별 분위수가 같은 바이트에서 품질을 지킬 가능성이 있다.

## 못 한 것

- ACE 의 GSP·RCR 표를 만들지 않았다. 동결 가중치 전체가 필요한데 랭크 파일은 노드마다 조각나 있다.
- T=1 라우트가 아니다(온도 0). 라우팅은 온도와 무관하지만 생성되는 토큰이 다르다.
- C=2 이상, 긴 문맥, 프리필 라우트는 보지 않았다.
- MoE 시간 ∝ 고유 전문가 수는 가정이다. V5 의 준비 단계(호출당 13.6 µs 중 일부)는 전문가 수와 무관하다.
