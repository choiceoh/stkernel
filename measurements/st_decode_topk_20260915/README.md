# 디코드 DSA 인덱서 선택을 커널 하나로 — 지평 마스크 + top-k 융합 (2026-09-15)

> 그날의 조사 — **2026-09-15 의 조사다.** 그날 참이었던 것이고 유지되지 않는다 — 이후 무엇이 바뀌었는지는 `MEASUREMENTS.md` 가 안다.

**판정이 아니다.** 아래 시간은 전부 **sm_120 (RTX 5050, 20 SM, GDDR)** 의 컴포넌트 측정이다. GB10 도 플릿도
아니고 onepass·수용률·step/s 는 재지 않았다. D17 대로 속도 주장은 플릿이 재야 끝난다 — 이 폴더는 그 티켓의 재료다.

## 무엇이 문제였나

`Glm53Net._select_rows` 는 DSA 층마다 두 가지를 샀다.

1. `_mask_horizon` — 스코어러가 낸 `[rows, n_cand]` fp32 에 `-inf` 를 덮어쓰는 **전체 read-modify-write**.
2. `torch.topk(..., sorted=False, out=(values, winners))` — 20k 열을 넘으면 토치의 다중 블록 경로다.
   **호출 하나가 커널 21 개**(digit count·cumsum·within-k 넷씩, scan_by_key·memset 둘씩, kth count·fill·gather
   하나씩)에 전역 작업공간을 쓰고, **아무도 읽지 않는 `values` fp32 버퍼**를 채우고, `pool_slots` 가 다시 좁히는
   int64 승자를 낸다.

원장이 이 자리를 이미 지목해 두었다(GPU 판정 15차): `[6912, 8192]` fp32 216 MB 를 14.5 ms 에 고르는 것은
**15 GB/s, 대역폭 바닥의 30분의 1**이고, "라딕스 두 패스가 맞는 모양"이라고 적혀 있었다.

## 바꾼 것

`engine/kernels/decode_topk.{cu,py}` — `st_dsa_select`, **런치 하나**, 작업공간 없음, 캡처 안전.

1. 행을 **한 번만** 읽는다(스레드당 float4). 지평은 레지스터 비교라 logits 를 건드리지 않는다.
2. 같은 스윕에서 원소마다 8비트 bin 을 **공유메모리에 남긴다**. sift 는 DRAM 대신 그 캐시를 읽는다.
3. 자르는 bin 은 **워프 하나**가 셔플로 고른다(블록 전체 8단 스윕 대신).
4. 후보는 **정렬 키를 id 옆에 달고** stash 에 들어간다 — 정제 라운드는 DRAM 으로 돌아가지 않는다.
5. 출력은 `pool_slots` 가 이미 받는 int32 이고, -1 패딩은 `topk_positions` 규약 그대로다.

폴백 둘, 둘 다 정확하다: 캐시에 안 맞는 넓은 행은 행을 두 번 읽고, stash 보다 넓은 bin 은 행을 상대로 정제한다.
`select()` 가 형상을 받지 않으면 `None` 을 돌려주고 호출자는 예전 경로를 그대로 탄다. **노브도 수치 분기도 없다.**

## 정확성의 근거 — 동점 규칙

키는 `(ordered_float_key(score) << 32) | ~index` 라 **정확한 동점은 낮은 pool id 가 이긴다.**
이것이 이 하드웨어에서 `torch.topk(sorted=False)` 가 하는 일인지를 먼저 실험으로 확인했다(`tie_rule.py`):
단일·다중 블록 형상에서 k 번째 경계에 평원을 강제로 만들어, **경계 동점이 실제로 발생한 89 행에서 불일치 0**.

`pool_slots` 는 **집합**을 받는다(승자를 토큰 위치 내림차순으로 다시 쓴다). 집합이 같으면 슬롯과 카운트가 같다.

## 수치 게이트 — 25,920 행 전부 일치 (`exactness_sm120.txt`)

| 행 | 1 · 8 · 16 · 20 |

**불일치 0 / 25,920.**

> 이 게이트가 실제 버그를 잡았다. 블록 폭을 런타임 인자로 바꾸면서 히스토그램 병합이 `tx < ST_RADIX` 로 남아
> 있었고, 256 보다 좁은 블록에서 상위 bin 이 0 으로 남아 **자르는 bin 을 틀리게 골랐다**. 그 상태로 잰
> 블록 폭 표는 깨진 커널을 잰 것이었다(n=1024 에서 T=128 이 "이겼던" 것). 고치고 다시 쟀다.

## 남은 거리 — 어디가 바닥인가 (`stages_sm120.txt`)

단계를 잘라 재면 **행을 읽는 스윕은 271 GB/s**, 이 상자 피크(~320)의 **85%** 다. 읽기는 이미 루프라인이고,
남은 것은 공유메모리 단계와 고정비다. 16×50688 에서 전체 22.7 µs 는 한 번 읽기 바닥(10.1 µs)의 2.2 배다.

**시도했다가 진 것 — 다시 하지 말 것:**

| 후보 | 결과 |
|---|---|
| 복제 히스토그램(1·2·4·8) | 전 arm 3% 안. 스윕은 카운터에서 경합하지 않는다 → 1 로 되돌림 |
| 워프 집계 원자연산(`__match_any_sync`) — 스윕 | 12 형상 154 → 185 µs. Blackwell 공유 원자연산이 이미 같은 주소를 합친다 |
| 워프 집계 원자연산 — 정제(후보가 한 bin 에 몰리는 퇴화 입력) | sift 8.1 → 8.9 µs. 여기서도 진다 |

**이긴 것:** bin 캐시(2 패스 → 1 패스, 16×50688 32.4 → 25.4), 공유 bin 을 4 바이트씩 읽기(바이트 읽기의
4-way 뱅크 충돌 제거, sift 10.2 → 8.1), stash 에 키 동봉(정제의 DRAM gather 제거), 형상별 블록 폭.

## 블록 폭 (`block_width_sm120.txt`)

`block_threads` 는 **스레드당 quad 하나, 라딕스(256)에서 바닥, 1024 에서 천장**이다. 아홉 형상 ×
{128, 256, 512, 1024} 에서 이 규칙이 아홉 개 전부 최적 arm 을 고른다(1024→256, 2048→512, 4096 이상→1024).

## 못 한 것

- **GB10 에서 안 돌렸다.** sm_120 과 sm_121a 는 같은 ISA 계열이지만 SM 수(20 대 48)와 메모리(GDDR 대 LPDDR)가
  다르다. 블록 폭 표와 "복제·워프집계가 진다"는 판정은 이 상자의 것이다.
- **onepass·수용률·step/s·품질 게이트 없음.** 서빙 tok/s 주장 없음.
- **TP4 없음.** 4랭크 부팅에서 `pool_slots` 슬롯·카운트 대조를 하지 않았다.
- **캡처 첫 호출의 `cudaFuncSetAttribute`** 가 플릿 캡처에서 문제없는지 확인하지 않았다(그래프 재생은 이 상자에서
  통과했다).
