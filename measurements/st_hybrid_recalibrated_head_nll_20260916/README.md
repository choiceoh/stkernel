# 하이브리드는 자기 교정을 새로 떠줘도 더 나쁘다 — 그리고 더 충실한 팩이 더 나쁜 점수를 냈다

2026-09-16. #911 의 GPTQ 전문가 하이브리드에 대한 2026-09-14 판정(+0.050 nats)에는 답이 안 된
반론이 하나 있었다: **그 판정의 헤시안은 하이브리드의 것이 아니었다.** 세 팔이 한 블롭 세트를
나눠 썼고, head NLL 이 "블롭을 합산한 팔에서 전문가가 얼마나 멀리 있나" 순서로 줄을 섰다
(`store.fits_weights` 의 docstring). 그래서 하이브리드에게 **자기 가중치 위에서 새로 합산한
헤시안**을 주고 다시 쟀다.

결과는 반론을 닫는다. 하이브리드는 여전히 더 나쁘고, **폭이 오히려 커졌다.**

## 잰 것

두 팔 모두 같은 커밋 `cc7abde71a472b84ed4ab6b2c734812b810f6be9`
(= `origin/main` @ `ad87ebb73` + `EXPERT_CAPTURE = True`), 같은 레인 `t,r,sf6,batch,q0`, 같은 플릿,
같은 창, **같은 코퍼스를 같은 방식으로**(133 대화 · 417,189 프롬프트 토큰).

| 팔 | 랭크 (`weight_layout`) | 블롭 |
|---|---|---|
| A | `st-glm53-9391-up-gate-full` (`b12x-up-gate-v1`) | 476, 오늘의 재교정본 |
| B | `st-glm53-hybrid-gptq-v1` (`modelopt-up-gate-bf16-dense-v1`) | 235, **이 팔 위에서 새로 합산** |

두 부팅 모두 교정 중이 아니었다 — `POST /v1/engine/calibration` 이 양쪽에서
`404 "every pack it serves was already calibrated"`, `foreign`/`RTN` 경고 0 (원장 규칙 5).

```
split                docs positions     nll A     nll B       B-A                95% CI
fit                   108     27631   2.78264   2.84694  +0.06430 [ +0.03921, +0.09066]
heldout                25      6400   2.99928   3.13285  +0.13357 [ +0.07241, +0.20504]
heldout-no-onepass     22      5632   2.99250   3.09967  +0.10717 [ +0.05324, +0.16868]
```

세 구간 모두 신뢰구간이 0 을 제외한다. 09-14 의 +0.050(fit)보다 **크다.**

## 차이는 헤드가 아니라 몸통에 있다

`head_compare` 는 각 부팅의 **자기 은닉상태 위에서 bf16 헤드**로도 같은 위치를 채점한다. 그 열이
서빙 헤드와 같은 폭으로 벌어져 있다(fit +0.06502, heldout +0.13499). 즉 손해는 헤드 양자화가
아니라 **몸통이 만드는 은닉상태**에서 나온다.

그리고 뒤집힌 지표가 하나 있다. 서빙 헤드가 자기 bf16 헤드에 대해 갖는 KL 은 **하이브리드 쪽이
더 작다** (4.91e-04 vs 5.78e-04). 하이브리드의 팩이 더 충실한데 모델은 더 나쁘다. "더 좋은 팩이
더 좋은 모델을 보장하지 않는다" 가 이 표에서 직접 보인다.

## 마지막 59 개를 마저 교정하자 오히려 나빠졌다

하이브리드의 235 개 사이트 중 176 개는 첫 교정 부팅에서 적재됐고, 59 개는 교정 예산에 밀려
다음 부팅으로 미뤄졌다(`58 tiles deferred to a later boot`). 그 상태로 한 번 재고(`B2partial`),
59 개를 마저 채운 뒤 다시 쟀다(`B`).

```
A vs B2partial (59 개 RTN)   fit +0.05591 [ +0.03053, +0.08111]
A vs B         (235 개 GPTQ)  fit +0.06430 [ +0.03921, +0.09066]
B2partial vs B                fit +0.00839 [ +0.00273, +0.01479]   <- 교정이 점수를 깎았다
```

그 59 개를 GPTQ 로 바꾸자 fit 에서 **+0.0084 nats 나빠졌고 신뢰구간이 0 을 제외한다.** KL 은 같이
내려갔다(6.76e-04 → 4.91e-04) — 또 한 번, 더 충실한 팩이 더 나쁜 점수를 냈다. 그 59 개는
34,164 행에서 적재됐고 첫 배치는 137,163 행이었다. 같은 날 `st_pack_levers_20260916` 이 잰
**얇은 헤시안은 헤시안이 없느니만 못하다**와 같은 방향이다.

판정은 어느 쪽이든 같다. 하이브리드는 59 개가 RTN 이든 GPTQ 든 프로덕션보다 나쁘다.

## 여기까지 오는 데 필요했던 것

하이브리드는 **부팅 자체가 안 됐다**(`st_hybrid_boot_block_20260916`, #1055). sf6 없는 동반 레인이
m=16 에서 직접 스캐터를 요구받아 `warmup_decode_experts` 에서 죽었다. #1056 이 그 한 자리를 고쳤고,
이 측정은 그 수정 위에서 처음으로 문에 닿은 하이브리드다(16:37:36).

교정 자체도 한 번 막혔다. 캡처 피드는 `max_tokens=1` 이라 **프리필만** 돌고, 드래프터는 디코드에서만
쓰이므로 드래프터 블롭이 한 행도 못 받았다. `progress()` 는 전 블롭의 **최소값**이라 그 0 이
`ROWS_FLOOR` 판정을 붙잡고 적재를 막았다. 디코드 트래픽을 따로 넣어 풀었다.

## 안 잰 것

- **속도.** #1056 은 sf6 없는 동반 레인에서 직접 레지스터 스캐터를 끈다. 프로덕션은 전 레인이
  sf6 라 영향이 없지만(동반 레인이 없다), **하이브리드는 그 셀을 못 쓴다.** 그래서 이 팔로
  #911 의 속도 주장은 재검증할 수 없다. 점수는 프리필로만 채점되므로 영향받지 않는다.
- **드래프터 블롭의 두께.** A 의 드래프터 블롭은 프로덕션 재교정본이고, B 의 것은 5,380 행에서
  적재됐다. 캡처는 프리필만 기록하므로 이 표의 숫자에는 들어오지 않지만, 두 팔이 대칭은 아니다.
- **서빙 판정(C=1 step/s) 없음.** 품질 게이트도 안 돌렸다.

플릿의 `~/glm53-logs/headnll3/` 에 있다.
