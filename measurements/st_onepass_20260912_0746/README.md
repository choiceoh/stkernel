## 해석상 제한

원패스의 기존 정답 게이트는 `reasoning_content`와 `content`를 합쳐 검사한다. 32K의 3/3은 **추론에 들어 있는 정답**으로 통과했다. 채널 진단에서 최종 `content`는 0자, `reasoning_content`는 2,913자이고 `finish_reason=length`이다. 2K 세 요청도 각각 400토큰에서 잘렸으므로 완결성 통과를 별도로 주장하지 않는다. 128K는 최종 답변까지 생성하고 `stop`으로 끝났다. 추론 예산과 최종 답변 확보가 후속 점검 항목이다.

TTFT는 기존 코드대로 **추론 또는 답변 중 첫 비어 있지 않은 스트림 조각**까지의 시간이다. 최종 답변이 화면에 나타날 때까지의 시간과 다르다.

이미 가동 중인 프로덕션에서 prefix cache를 켠 상태로 실행했다. 최초 시도는 결과 저장 파일의 상대 경로 문제를 발견해 중단했으며, 2K 완료 후 32K 요청까지 제출한 상태였다. 중단 기록은 `attempt1-aborted/`에 보관했다. 이 시도가 32K prefix cache를 데웠을 수 있으므로 32K의 2.679초 및 단순 입력/TTFT 값 12,150 tok/s를 **전체 32K 프리필 계산 성능으로 사용하지 않는다**. 재시도는 서버가 다시 유휴 상태가 된 후 시작했다. 최초 시도 데이터는 완주 결과에 합치지 않았다.

128K의 입력/TTFT는 약 1,996 tok/s이다. 캐시를 비우거나 재부팅한 실행이 아니며, 정확한 cache-hit 토큰 수를 수집하지 않았다. 원본 JSON의 `cold_s`/`warm_s`는 기존 하네스 필드 이름을 보존한 것으로 새 부팅의 cold/warm 구분을 뜻하지 않는다. 동일 조건의 vLLM 비교 실행은 하지 않았다.
