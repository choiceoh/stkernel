Runtime: local arm64 Linux CPU container, torch 2.14.0+cpu, Triton 3.8.0,
CUDA devices hidden. Source hashes and individual CPU test durations are in
the mock record; compiled source/cubin hashes and shared-memory sizes are
in the compile record. PTX/cubins can be regenerated by the offline probe.
The W4A8 interpreter record uses torch's RTNE conversion after executing
native scaling arithmetic because Triton 3.8's interpreter rounds FP8 ties
upward. The generated native code uses FP8 `cvt.rn`/MMA; it was not executed.

Storage arithmetic for 16 nodes, 16 KDA heads, dimension 128:
16 MiB full per-node states versus 384 KiB factors plus one 1 MiB initial
state per KDA layer. This excludes additional commit/activation scratch.
W4A8 MLP M=16,H=4096,I=3072 declares 6,473,456 scratch bytes and 824 tasks.
The separate W4A4 plan declares 12,742,096 bytes and 3,184 tasks.
Additional resident weight bytes are zero for both packed bindings.

These numbers are allocation formulas, not measured process memory or speed.
Native liveness/numerics, real-weight quality, route-prediction usefulness,
C=1/C=4 tok/s, TTFT, acceptance and 32K/128K behavior remain unmeasured.
No fleet queue was reserved, process booted or GPU used.
