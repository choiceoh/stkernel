# greedy argmax 의 두 발사, 4·2·1 warps — GB10 단일 GPU 레인 (2026-09-19)

> 그대로 두는 기록 — 캐리 D5(`engine/QWEN38_CARRY.md`: "argmax partials/finish 를 한 warp 로", GLM #1004 의 이식)의 판정과 원시 로그다.
> 뒤 실행은 이 파일을 고치지 않고 새 기록을 남긴다.

**결론: 기각.** `engine/kernels/common/vocab_candidates.argmax_key` 의 두 발사(`_argmax_partials`, `_argmax_finish`)는 GB10 에서
4 warps(Triton 기본값, 지금까지의 발사)가 가장 빠르거나 동률이다. 1 warp 는 모든 행 수에서 느리다(+7~+75%). 기본값은 그대로 두고
`ARGMAX_WARPS = 4` 로 **선언**만 했다(같은 컴파일 결과, 동작·바이트 변화 없음). 엔진 속도 주장은 없다(헌장 D17) — 커널 컴포넌트 시간이다.

## 왜 #1004 의 결론이 여기로 넘어오지 않는가

#1004 는 후보 선택(`select_logits` / `_select`)을 1 warp 로 내려 RTX 5050 에서 −36% 를 얻었다. 그 프로그램은 구간마다 정수 MAX 축약을
**16 번 연달아** 돌려서, 4 warps 에서는 매 단계 warp 사이 교환(PTX `bar.sync` 47 회)을 냈다. greedy 의 프로그램은 1,024 열(또는 행의 부분
결과 수십 개)에 대한 MAX **한 번**이다 — 교환은 한 번뿐이고, 스레드가 많은 쪽이 축약 트리가 얕다. 그래서 같은 처방이 반대로 나온다.

## 측정

티켓 `vocab-argmax-warps-0919`, 트리 `59077c6a`(브랜치 `qwen38-argmax-one-warp`), 프로브 `probes/engine_kernel_check.py --lanes vocab_argmax`
(= `probes/engine_vocab_selection.argmax_run`). 장치 NVIDIA GB10(sm_121a), 이미지 `st-engine:glm53`(torch 2.13.0+cu132, triton 3.7.1),
프로덕션 `st-glm53` 옆(예산 8 GiB, 플릿 임대 없음). 원시 로그: [gb10-59077c6a.log](gb10-59077c6a.log).

- 입력: BF16 logits 의 **strided** 샤드(`full[:, ::2]`), `start = 3 × 폭`, 디코드 가능 컷 = 폭 − 1,000(마지막 랭크의 패딩 id).
  Qwen3.8 의 샤드(248,320 / 4 = 62,080 열)를 디코드 사다리의 행 수(C × (K+1) = 2..32)에서, GLM-5.3 의 샤드(38,720 열)를 그 검증 스텝의
  행 수(1·7·14·28)에서.
- **정합 게이트(타이밍 전, 전부 통과):** 캡처한 그래프를 입력을 바꿔 가며 네 번 재생 — 무작위, 한 부분 결과 안의 동률(가장 낮은 id),
  두 부분 결과에 걸친 동률, `±0`·`±NaN`·`±inf` — 매번 4·2·1 warps 와 서빙 진입점(`argmax_key`)의 패킷이 `engine/modules/vocab.argmax` 의
  CPU 분기(= `tests/test_engine_vocab.py` 가 `torch.argmax` 에 붙들어 둔 식)와 **바이트 동일**. 키가 정수라 warps 가 패킷을 바꿀 수 없다.
- 타이밍: 호출 16 개를 담은 그래프를 32 회 재생 × 8 표본(팔 순서를 앞뒤로 뒤집어 가며), 호출당 µs. 중앙값(최솟값).
